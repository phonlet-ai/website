Phonlet Wake for Python.

A wheel with the engine built in, for prototypes, research, and Linux devices.

The Python SDK is a wheel that bundles the engine and uses NumPy. It needs no compiler, lexicon, or network at runtime. It is tested on CPython 3.12 on Linux x64.

Example

wake.py
1from phonlet_wake import Wake2 3# A phrase is its pronunciations and two calibrated thresholds.4hey_kettle = {5    "name": "hey kettle",6    "pronunciations": [[16, 13, 20, 11, 31, 3, 21]],7    "threshold_loose": -1.21875,8    "threshold_strict": -0.8740234375,9    "endpoint": True,10}11 12# One engine and one model for every phrase.13with Wake.create(model="en-1.pwake", keywords=[hey_kettle],14                 sensitivity=0.5) as wake:15    # Push 16 kHz mono int16 NumPy arrays in chunks of any size.16    for pcm in audio_chunks():  # your microphone or file17        for hit in wake.process(pcm):18            print("Wake word:", hit.keyword)

How it works

  1. Make a keyword file for your phrases with the generator: each phrase gets its pronunciations and its loose and strict thresholds, calibrated for this model.
  2. Create a Wake with the model and your phrases, inside a with block so it closes on success and on errors. Pass the keyword file from the generator as a path, as the parsed dict, or as phrases written in code; a file that names its model is checked against it by SHA-256.
  3. Pass int16 NumPy arrays to process(); it returns the detections in that chunk.
  4. Call finish() at the end of a stream to see how many trailing samples did not fill a frame.

Good to know

  • Audio is mono, 16 kHz, signed 16-bit PCM. Push chunks of any size; the engine buffers them into 512-sample (32 ms) frames.
  • A phrase always comes with its thresholds: they are calibrated for that phrase and that model, and the engine needs them to decide when it was said. The generator makes them from text (phonletai.com/generator, or the wake-threshold command) and writes them into your keyword file.
  • Each detection has keyword_id, keyword, keyword_index, frame_index, sample_index, time_seconds, and the sensitivity used.
  • Microphone input is an optional extra (sounddevice with PortAudio); detection itself has no audio dependency.
